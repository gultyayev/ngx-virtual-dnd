# Animations and haptics

By default, rows displaced by the placeholder jump to their new position, and the preview disappears on drop. Provide `VDND_ANIMATION_CONFIG` to make rows slide and the dropped item glide into its slot instead. For feedback on every step, such as a haptic tick, listen to `(placeholderMove)`.

:::info Added in 3.2.0
Both features are new in 3.2.0, which is currently a pre-release. Install it with `npm install ngx-virtual-dnd@next`.
:::

## Shift animation

The animation is opt-in. Provide the config app-wide, or in a component's `providers` to animate only the lists in that subtree:

```ts
// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { VDND_ANIMATION_CONFIG } from 'ngx-virtual-dnd';

export const appConfig: ApplicationConfig = {
  providers: [{ provide: VDND_ANIMATION_CONFIG, useValue: { shiftDuration: 200 } }],
};
```

| Option          | Default                      | Meaning                                                            |
| --------------- | ---------------------------- | ------------------------------------------------------------------ |
| `shiftDuration` | `200`                        | Slide duration in ms. `0` turns it off                             |
| `shiftEasing`   | `cubic-bezier(0.2, 0, 0, 1)` | Any CSS easing function                                            |
| `dropDuration`  | `200`                        | [Drop animation](#drop-animation) duration in ms. `0` turns it off |
| `dropEasing`    | `cubic-bezier(0.2, 0, 0, 1)` | Any CSS easing function                                            |

- The slide is a `transform` animation, so it stays on the compositor. It works with virtual scrolling and with [dynamic heights](/guide/features/dynamic-heights).
- It is skipped when the user has turned on reduced motion (`prefers-reduced-motion: reduce`).
- If the placeholder moves again mid-slide, rows continue from where they currently are.
- Drop positions are calculated from geometry, so a row that is still sliding never changes where an item lands.
- Rows also slide on drop or cancel. After a drop they usually already sit in their final slots, so a slide in progress simply finishes. After a cancel, displaced rows slide back.
- The slide is added on top of any `transform` you set on rows, so your own transforms are kept.

The config is read each time an animation starts, so a getter can switch it at runtime, for example from a user setting:

```ts
{
  provide: VDND_ANIMATION_CONFIG,
  useFactory: () => {
    const settings = inject(SettingsService);
    return {
      get shiftDuration() {
        return settings.reduceAnimations() ? 0 : 200;
      },
    };
  },
}
```

## Drop animation

With the same config, releasing an item no longer makes the preview vanish. The preview glides from where you let go onto the item's final position, then disappears. The real item stays invisible until the preview lands on it, so it is never shown twice. A cancelled drag (<kbd>Escape</kbd>) glides back to where the item started.

- It is purely visual. `drop` and `dragEnd` fire right away, and the list is already in its new order while the preview travels.
- The preview lands on the item as it is rendered after your `(drop)` handler. Commit the move in the handler (for example with `moveItem()` or `reorderItems()`). If you commit later, for example after a server call, the preview glides back to the item's old slot.
- If the item is not rendered, or is scrolled out of its list's view, the preview fades out where it was released.
- Starting a new drag ends the animation at once.
- While it plays, the preview box has the class `vdnd-drag-preview-dropping`.
- It is skipped under reduced motion, like the shift animation. Set `dropDuration: 0` to keep only the shift animation.

### Where it applies

Rows animate in `<vdnd-sortable-list>`, `<vdnd-virtual-scroll>` and every `*vdndVirtualFor` list, including those inside `<vdnd-virtual-viewport>` and `<vdnd-virtual-content>`.

:::warning
Do not add your own CSS `transition` on the rows' `transform` or `top` to get this effect. Rows are repositioned by layout (or by an inline `top` in a `*vdndVirtualFor` placed directly in a `vdndScrollable`), and a transition on either property competes with the built-in slide.
:::

## Placeholder move events

`vdndDroppable` and `<vdnd-sortable-list>` emit `placeholderMove` each time the placeholder moves within that list, which is every time rows are displaced:

```angular-html
<vdnd-sortable-list ... (placeholderMove)="onPlaceholderMove($event)" />
```

```ts
onPlaceholderMove(event: PlaceholderMoveEvent): void {
  navigator.vibrate?.(10); // or Haptics.selectionChanged() from @capacitor/haptics
}
```

The event fires when the placeholder enters the list and on every move inside it. It does not fire for the initial pick-up, when the placeholder still sits in the item's own slot, or when the placeholder leaves the list.

| Field               | Meaning                                                                             |
| ------------------- | ----------------------------------------------------------------------------------- |
| `draggableId`       | The dragged item                                                                    |
| `sourceDroppableId` | The list the drag started in                                                        |
| `droppableId`       | The list the placeholder moved within                                               |
| `previousIndex`     | The previous insertion index, or `null` when the placeholder just entered this list |
| `currentIndex`      | The new insertion index                                                             |
| `data`              | The dragged item's `vdndDraggableData`                                              |

Both indexes follow the same convention as [`DropEvent.destination.index`](/api/events#dropevent): the index the item would get if it were dropped now. For the first move in the source list, `previousIndex` is the item's original index.

Each event reports one placeholder update. During a fast pointer drag the placeholder can skip rows between updates, so `currentIndex` may differ from `previousIndex` by more than one. Keep the handler cheap: it runs during the drag.
