# Accessibility

Every draggable can be moved with the keyboard, with nothing to enable. The exception is an item that is itself a text field, a `select`, a checkbox or an editable element, which needs a focusable drag handle (see [Controls in items](#controls-in-items)).

## Keyboard

| Key                       | Not dragging                   | During a keyboard drag                                                                                      |
| ------------------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| <kbd>Tab</kbd>            | Moves focus between draggables | Cancels the drag                                                                                            |
| <kbd>Space</kbd>          | Picks up the focused item      | Drops                                                                                                       |
| <kbd>Enter</kbd>          | —                              | Drops                                                                                                       |
| <kbd>↑</kbd> <kbd>↓</kbd> | —                              | Moves the target position                                                                                   |
| <kbd>←</kbd> <kbd>→</kbd> | —                              | Moves to the neighbouring list in the same group, by on-screen position, skipping disabled and hidden lists |
| <kbd>Escape</kbd>         | —                              | Cancels. Also cancels pointer drags.                                                                        |

Each arrow key scrolls the list, and the scroll containers around it, to show where the item will land. So the keyboard reaches every item in a virtual list, not just the rendered ones.

### Hidden lists

A hidden list is still in the page but not shown: `display: none` on it or an ancestor (an inactive tab, a column hidden by a media query), `visibility: hidden`, or a size of zero.

- The arrow keys skip it, and a pointer drag falls through it to the list underneath, if any, as it does for a disabled list.
- A list disabled or hidden (`display: none` or `visibility: hidden`) after a keyboard drag moved into it takes no drop: <kbd>Space</kbd> or <kbd>Enter</kbd> ends the drag with no destination, and focus returns to the item in its own list.

### Controls in items

Pressing <kbd>Space</kbd> in a control inside an item, such as a text field or a button, types into or clicks the control instead of picking the item up, unless the control is the drag handle.

An item that is itself a text field, `textarea`, `select`, checkbox or editable element keeps <kbd>Space</kbd> too, so only <kbd>Space</kbd> on a focusable drag handle inside it picks it up:

- An `input`, `textarea` or `select` can't hold a handle. Make a row element the draggable and put the control inside it.
- A `[contenteditable]` block needs a grip such as `<span class="grip" contenteditable="false" tabindex="0" role="button" aria-label="Drag block">`. See [Editable content](/guide/features/drag-behavior#editable-content).

After a keyboard drop or cancel, focus returns to the draggable element itself. For an editable block that puts the caret in the block; press <kbd>Tab</kbd> to reach its grip again.

## Managed for you

- `tabindex="0"` on draggables (`-1` when disabled)
- After a keyboard drag, focus returns to the moved item in its new position
- `aria-grabbed` on draggables and `aria-dropeffect="move"` on droppables

`aria-grabbed` and `aria-dropeffect` are deprecated since ARIA 1.1, and most screen readers ignore them. They do not tell screen reader users that an item can be dragged, how to drag it, or where it is. Add instructions and announcements yourself, as described below.

## Instructions

Nothing tells a screen reader user that <kbd>Space</kbd> picks an item up. Describe the keys once in a hidden element and point every draggable at it with `aria-describedby`. Screen readers read the description when the item gets focus:

```angular-html
<p id="drag-instructions" hidden>
  Press Space to pick up. Use the arrow keys to move, Space to drop and Escape to cancel.
</p>

<ng-template #taskTpl let-task>
  <div [vdndDraggable]="task.id" aria-describedby="drag-instructions">{{ task.title }}</div>
</ng-template>
```

## Screen reader announcements

The library does not make announcements itself, so wording and translations stay in your hands. The events carry everything you need: `(dragStart)` for the pick-up, `(placeholderMove)` for every step and `(dragEnd)` for the result. Render the messages in a live region:

```ts
@Component({
  template: `
    <p id="drag-instructions" hidden>
      Press Space to pick up. Use the arrow keys to move, Space to drop and Escape to cancel.
    </p>

    <div vdndGroup="tasks">
      <ng-template #taskTpl let-task>
        <div
          [vdndDraggable]="task.id"
          [vdndDraggableData]="task"
          aria-describedby="drag-instructions"
          (dragStart)="onDragStart($event)"
          (dragEnd)="onDragEnd($event)"
        >
          {{ task.title }}
        </div>
      </ng-template>

      <vdnd-sortable-list
        droppableId="tasks"
        [items]="tasks()"
        [itemHeight]="48"
        [containerHeight]="400"
        [itemIdFn]="taskId"
        [itemTemplate]="taskTpl"
        (drop)="onDrop($event)"
        (placeholderMove)="onPlaceholderMove($event)"
      />
    </div>

    <div class="sr-only" aria-live="assertive">{{ announcement() }}</div>
  `,
})
export class TasksComponent {
  readonly #dragState = inject(DragStateService);
  readonly announcement = signal('');

  onDragStart(event: DragStartEvent): void {
    const task = event.data as Task;
    this.announcement.set(
      `Picked up ${task.title}, position ${event.sourceIndex + 1} of ${this.tasks().length}`,
    );
  }

  onPlaceholderMove(event: PlaceholderMoveEvent): void {
    // Pointer users see the placeholder move; announce keyboard steps only
    if (!this.#dragState.isKeyboardDrag()) return;
    this.announcement.set(`Position ${event.currentIndex + 1} of ${this.tasks().length}`);
  }

  onDragEnd(event: DragEndEvent): void {
    this.announcement.set(
      event.destinationIndex === null
        ? `Cancelled. Back at position ${event.sourceIndex + 1}`
        : `Dropped at position ${event.destinationIndex + 1}`,
    );
  }

  // tasks, taskId and onDrop as in the Quick start
}
```

`.sr-only` is the usual visually-hidden utility (`position: absolute; width: 1px; height: 1px; overflow: hidden; clip-path: inset(50%);`).

With [multiple lists](/guide/essentials/multiple-lists), also name the list in the step message: `event.droppableId` is the list the placeholder is in.

## Touch

Touch drags work out of the box. If your lists also need to scroll by touch, add a short [`dragDelay`](/guide/features/drag-behavior#threshold-and-delay) so a quick swipe scrolls and a press-and-hold drags.
