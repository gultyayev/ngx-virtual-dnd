# Drag behavior

These inputs change when a drag starts and how it moves. All of them are optional.

Only one drag runs at a time. While an item is being dragged, with the pointer or the keyboard, pressing another item (a second finger on a touch screen) or pressing <kbd>Space</kbd> on it does not start a second drag.

## Drag handles

Set `dragHandle` to a CSS selector, and only presses inside a matching element in the row start a drag (an element around the row that matches doesn't count). The rest of the row stays free for selecting text, clicking and so on.

Make the handle a non-interactive element such as a `<span>`. Presses inside a button in the row never start a drag, as the next section explains. Keyboard dragging is unaffected: the whole row stays focusable.

## Interactive children

Controls inside a row keep working. Pressing a `button`, `input`, `textarea`, `select` or `[contenteditable]` element inside a row never starts a drag, and <kbd>Space</kbd> on one types or clicks instead of picking the row up. Only controls inside the row count: a control around the list doesn't stop a drag, and an element with `contenteditable="false"` is not editable, so it doesn't count either.

Other controls are not recognized, for example an element with `role="switch"`, or a web component whose input is in its shadow DOM. Add the `no-drag` class to them: it covers the element and everything inside it. For a web component, add it to the component element itself: presses inside its shadow DOM reach the row as presses on that element.

Only the primary mouse button starts a drag. To turn dragging off completely, use [`disabled`](#disabling).

### Rows that are controls

- **A button** (`<button vdndDraggable>`, or an `input` of type `button`, `submit`, `reset` or `image`) drags like any other row.
- **Any other control** (a text field, a checkbox, a `select` or a `[contenteditable]` element) keeps its own press and <kbd>Space</kbd>: a press focuses, opens, toggles or places the caret, and <kbd>Space</kbd> types a space, toggles or opens. Only a [drag handle](#drag-handles) inside it starts a drag. An `input`, `textarea` or `select` can't hold a handle, so make a row element the draggable and put the control inside it.

### Editable content

Rows inside a `[contenteditable]` editor drag like any other row, so pressing one starts a drag instead of placing the caret. To keep their text editable with the mouse, give them a drag handle. In Chromium, <kbd>Space</kbd> on such a row goes to the editor instead of picking the row up; Firefox and Safari pick it up.

A block that is its own editing host moves only by a handle. Make the handle `contenteditable="false"`, and focusable so keyboard users can reach it:

```angular-html
<div contenteditable [vdndDraggable]="block.id" dragHandle=".grip">
  <span
    class="grip"
    contenteditable="false"
    tabindex="0"
    role="button"
    aria-label="Drag block"
  >
    ⠿
  </span>
  {{ block.text }}
</div>
```

- Presses on the grip start a drag, and the rest of the block stays editable.
- <kbd>Space</kbd> in the text types a space, and <kbd>Space</kbd> on the grip picks the block up.
  Without a focusable handle, the block can't be moved with the keyboard.
- After a keyboard drop or cancel, focus returns to the block itself, placing the caret in it. <kbd>Tab</kbd> reaches the grip again.

### Reference

What starts a drag depends on where the pointer press lands, or on which element has focus when <kbd>Space</kbd> is pressed:

| Element                                                                         | Pointer press starts a drag  | <kbd>Space</kbd> on it picks the row up              |
| ------------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------------- |
| The row                                                                         | Yes                          | Yes                                                  |
| A `button`, `input`, `textarea`, `select` or `[contenteditable]` inside the row | No                           | No                                                   |
| An element with the `no-drag` class, and everything inside it                   | No                           | No                                                   |
| The row, with `no-drag` on the draggable element itself                         | No                           | Yes                                                  |
| The row outside the handle, when `dragHandle` is set                            | No                           | Yes, unless the row is a control other than a button |
| A drag handle that is not a control, such as a `<span>`                         | Yes                          | Yes, when it is focusable (`tabindex="0"`)           |
| A drag handle that is a `button`                                                | No                           | Yes                                                  |
| A row that is a button                                                          | Yes                          | Yes                                                  |
| A row that is another control                                                   | Only from a handle inside it | Only on a focusable handle inside it                 |
| A row inside a `[contenteditable]` editor                                       | Yes                          | Yes, except in Chromium                              |

## Threshold and delay

```angular-html
<div [vdndDraggable]="task.id" [dragThreshold]="10" [dragDelay]="200">{{ task.title }}</div>
```

| Input           | Default | Effect                                                                                                                                                   |
| --------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dragThreshold` | `5`     | How far (px) the pointer must move before the drag starts. Stops clicks from turning into drags.                                                         |
| `dragDelay`     | `0`     | How long (ms) the pointer must be held first. Moving past the threshold before the delay ends cancels the drag attempt, so touch users can still scroll. |

When the delay has passed, the element gets the `vdnd-drag-pending` class. Style it so users can see the item is ready to move:

```css
.vdnd-drag-pending {
  transform: scale(1.02);
  box-shadow: 0 4px 12px rgb(0 0 0 / 0.15);
}
```

A delay of 150–250 ms works well on touch devices.

## Axis locking

```angular-html
<div [vdndDraggable]="task.id" lockAxis="x">{{ task.title }}</div>
```

`lockAxis` names the axis that is **frozen**:

- `'x'`: the X axis is frozen, so the item moves only vertically
- `'y'`: the Y axis is frozen, so the item moves only horizontally

:::warning Migrating from Angular CDK
This is the opposite of CDK's `cdkDragLockAxis`, where `'x'` means the item moves along the X axis.
:::

## Constraining to the container

```angular-html
<vdnd-sortable-list [constrainToContainer]="true" ... />
<!-- or -->
<div vdndDroppable="tasks" [constrainToContainer]="true">...</div>
```

The preview cannot leave the container. Holding it against the container's top or bottom edge drops the item at the first or last position once the list is scrolled to that end; until then the drop position is the visible row at that edge, while autoscroll, when it runs, moves the list there. The container is the nearest `vdndScrollable` ancestor if there is one, and the droppable otherwise.

When a sticky header or footer inside the `vdndScrollable` element covers part of it, pass their heights as `scrollInsetTop` and `scrollInsetBottom` so the preview stays clear of them (see [Sticky headers and footers](/guide/features/page-scroll#sticky-headers-and-footers)).

## Disabling

Every draggable, droppable and list accepts `disabled`:

```angular-html
<div [vdndDraggable]="task.id" [disabled]="task.locked">{{ task.title }}</div>

<!-- Nothing can be dropped into this list -->
<vdnd-sortable-list [disabled]="locked()" ... />
```

- A **disabled draggable** cannot be picked up. It gets `tabindex="-1"` and the `vdnd-draggable-disabled` class.
- A **disabled droppable** (or `<vdnd-sortable-list>`) is skipped as a target. Its items can still be dragged out, so for a read-only list also disable the draggables in its item template. The pointer passes through to whatever enabled droppable is underneath, and keyboard left/right navigation skips it. Releasing over it emits no `(drop)`. `(dragEnd)` still fires with `destinationIndex: null`. It gets the `vdnd-droppable-disabled` class.
