# Drag behavior

These inputs change when a drag starts and how it moves. All of them are optional.

## Drag handles

Set `dragHandle` to a CSS selector, and only presses inside a matching element start a drag. The rest of the row stays free for selecting text, clicking and so on.


The handle can be any element, a button included: pressing the handle, or a control inside it, always starts a drag. Keyboard dragging is unaffected: the whole row stays focusable.

## Interactive children

Presses inside a control never start a drag, so controls inside rows keep working. Controls are `button`, `input`, `textarea`, `select`, `summary` and `[contenteditable]` elements, and elements with one of the ARIA roles `button`, `checkbox`, `combobox`, `radio`, `searchbox`, `slider`, `spinbutton`, `switch` or `textbox`. Controls inside a web component's shadow DOM count too, such as the input of an Ionic or Shoelace text field. The row itself never counts, so a `<button vdndDraggable>` still drags, and neither do elements around the row. Only the primary mouse button starts a drag.

To exclude another element, add the `no-drag` class. It applies only to the exact element that is pressed, not to its children. Use it for controls that can't be recognized: a clickable element without a role, or a web component whose shadow root is closed. For a web component, add it to the component element itself: presses inside its shadow DOM reach the row as presses on that element.

A row whose content is itself a control doesn't start drags from it either, for example an `ion-item` with the `button` attribute, which wraps its content in a button. Put `vdndDraggable` on that element itself, or add a drag handle.

The same goes for the keyboard: <kbd>Space</kbd> pressed in one of these controls (or on a `no-drag` element) inside a row types a space, clicks the button or toggles the switch instead of picking the row up. The drag handle is the exception: <kbd>Space</kbd> on it picks the row up, even when it is a control.

## Threshold and delay

```angular-html
<div [vdndDraggable]="task.id" [dragThreshold]="10" [dragDelay]="200">{{ task.title }}</div>
```

| Input           | Default | Effect                                                                                                                                                   |
| --------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dragThreshold` | `5`     | How far (px) the pointer must move before the drag starts. Stops clicks from turning into drags.                                                         |
| `dragDelay`     | `0`     | How long (ms) the pointer must be held first. Moving past the threshold before the delay ends cancels the drag attempt, so touch users can still scroll. |

When the delay has passed, the element gets the `vdnd-drag-pending` class. Style it so users can see the item is ready to move:

```css
.vdnd-drag-pending {
  transform: scale(1.02);
  box-shadow: 0 4px 12px rgb(0 0 0 / 0.15);
}
```

A delay of 150–250 ms works well on touch devices.

## Axis locking

```angular-html
<div [vdndDraggable]="task.id" lockAxis="x">{{ task.title }}</div>
```

`lockAxis` names the axis that is **frozen**:

- `'x'`: the X axis is frozen, so the item moves only vertically
- `'y'`: the Y axis is frozen, so the item moves only horizontally

:::warning Migrating from Angular CDK
This is the opposite of CDK's `cdkDragLockAxis`, where `'x'` means the item moves along the X axis.
:::

## Constraining to the container

```angular-html
<vdnd-sortable-list [constrainToContainer]="true" ... />
<!-- or -->
<div vdndDroppable="tasks" [constrainToContainer]="true">...</div>
```

The preview cannot leave the container, and the drop position snaps to its edges. The container is the nearest `vdndScrollable` ancestor if there is one, and the droppable otherwise.

## Disabling

Every draggable, droppable and list accepts `disabled`:

```angular-html
<div [vdndDraggable]="task.id" [disabled]="task.locked">{{ task.title }}</div>

<!-- Nothing can be dropped into this list -->
<vdnd-sortable-list [disabled]="locked()" ... />
```

- A **disabled draggable** cannot be picked up. It gets `tabindex="-1"` and the `vdnd-draggable-disabled` class.
- A **disabled droppable** (or `<vdnd-sortable-list>`) is skipped as a target. Its items can still be dragged out, so for a read-only list also disable the draggables in its item template. The pointer passes through to whatever enabled droppable is underneath, and keyboard left/right navigation skips it. Releasing over it emits no `(drop)`. `(dragEnd)` still fires with `destinationIndex: null`. It gets the `vdnd-droppable-disabled` class.
