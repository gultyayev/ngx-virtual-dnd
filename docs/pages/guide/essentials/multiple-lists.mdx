# Multiple lists

Lists that share a **group** exchange items. Drag a row from one column to the other:


Three details make this work:

- Both `<vdnd-sortable-list>` elements are inside the same `vdndGroup`, and so is the shared item template.
- **Both lists bind `(drop)`.** The event fires on the destination list only, so a list without a handler silently rejects items.
- `moveItem()` receives every list, keyed by `droppableId`. It handles moves within a list as well as between lists. If a droppable ID is missing from the map, the drop is ignored and a warning is logged in dev mode.

## A board with any number of columns

Keep one signal per column and build the map for `moveItem()` from your column list:

```ts
interface Column {
  id: string;
  title: string;
  tasks: WritableSignal<Task[]>;
}

readonly columns: Column[] = [
  { id: 'todo', title: 'To do', tasks: signal([]) },
  { id: 'doing', title: 'In progress', tasks: signal([]) },
  { id: 'done', title: 'Done', tasks: signal([]) },
];

readonly lists = Object.fromEntries(this.columns.map((c) => [c.id, c.tasks]));

onDrop(event: DropEvent): void {
  moveItem(event, this.lists);
}
```

```angular-html
<div class="board" vdndGroup="board">
  <ng-template #taskTpl let-task>
    <div class="row" [vdndDraggable]="task.id">{{ task.title }}</div>
  </ng-template>

  @for (column of columns; track column.id) {
    <section>
      <h3>{{ column.title }}</h3>
      <vdnd-sortable-list
        [droppableId]="column.id"
        [items]="column.tasks()"
        [itemHeight]="48"
        [containerHeight]="480"
        [itemIdFn]="taskId"
        [itemTemplate]="taskTpl"
        (drop)="onDrop($event)"
      />
    </section>
  }
</div>
```

Draggable IDs must be unique across **all** columns, because drag state is shared across the whole app.

## Controlling where items can go

| Goal                                    | How                                                                          |
| --------------------------------------- | ---------------------------------------------------------------------------- |
| Lists that never exchange items         | Put them in different groups (separate `vdndGroup` elements)                 |
| A list that temporarily accepts nothing | `[disabled]="true"` on the list or on `vdndDroppable`                        |
| Items that cannot be moved              | `[disabled]="true"` on the draggable                                         |
| Accept only some items                  | Bind `disabled` from the drag state, see [below](#accepting-only-some-items) |

A disabled droppable is skipped completely. The pointer passes through it to whatever is underneath, and the keyboard's left and right arrows skip it. See [Drag behavior](/guide/features/drag-behavior#disabling).

Releasing over nothing, or over a disabled list, emits no `(drop)`. The item returns to where it started.

## Accepting only some items

There is no predicate input that rejects some items. Returning early from `(drop)` keeps your data unchanged, but during the drag the target list still opens a slot for the item, so the user sees a drop that then does not happen.

Instead, disable the list while an item it does not accept is being dragged. `DragStateService` tells you which item that is, and a droppable whose `disabled` changes mid-drag is skipped from the next frame:

```ts
readonly #dragState = inject(DragStateService);

// Only tasks with an assignee can move to "Done"
readonly doneRejectsDrag = computed(() => {
  const task = this.#dragState.draggedItem()?.data as Task | undefined;
  return task !== undefined && !task.assignee;
});
```

```angular-html
<ng-template #taskTpl let-task>
  <div class="row" [vdndDraggable]="task.id" [vdndDraggableData]="task">{{ task.title }}</div>
</ng-template>

<vdnd-sortable-list droppableId="done" [disabled]="doneRejectsDrag()" ... />
```

The pointer then passes over the list without a placeholder, and the keyboard's left and right arrows skip it. Style `.vdnd-droppable-disabled` to show that the list does not accept the item.
